## Batas yang masih perlu ditutup

1. **Bukti pembayaran mandiri Wali sebelum onboarding** belum tersedia. Admin dapat menyelesaikan tagihan kandidat secara manual; bukti dari Wali baru dapat dikirim sesudah hubungan akun–santri aktif. Jika alur mandiri sebelumnya menjadi kebutuhan produk, desain dan tes perlu ditambahkan pada fase berikutnya.
2. **PPOB/payment gateway** dikeluarkan dari rilis awal sesuai keputusan pemilik produk. Modul disembunyikan dan permission lama tidak dapat mengaktifkannya; integrasi provider, settlement/reversal, dan rekonsiliasi menjadi pekerjaan fase berikutnya.
3. **Notifikasi keluar** (email/WhatsApp/SMS) memerlukan konfigurasi dan uji provider masing-masing environment. CI tidak mengirim ke provider nyata.
4. **Pemakaian data lama** tidak diperlukan untuk dummy Firestore sesuai keputusan pemilik. Jika suatu pelanggan kelak memerlukan arsip riil, itu menjadi proyek migrasi terpisah dengan pemetaan dan persetujuan pelanggan.
5. **Database Supabase target** `ptsasgdvgrbdtgyqieie` belum dapat dibaca untuk rekonsiliasi ledger. Migration belum diterapkan ke target; backend harus merekonsiliasi dan melakukan rehearsal sebelum menyalakan flag runtime.

## Kesimpulan

Hubungan terpenting PPDB → onboarding → Santri/Wali/NIS/kamar dan Finance memiliki implementasi transaksional serta coverage CI sintetis. Batas rilis PPOB telah ditetapkan; fitur bukti Wali sebelum onboarding dan provider notifikasi masih perlu keputusan/konfigurasi pada roadmap rilis. PR #13 telah merged ke `main` sebagai baseline source yang diuji; merge tidak berarti database live sudah dimigrasikan atau ERP siap dijual. Deployment hosting, ledger target, login, dan UAT tetap dikerjakan tim penerapan.
